# 桌面黑洞与桌面反畸变

作者：**syh**（GitHub：`warmowinter`）

这是一个运行在 Windows 桌面上方的实时画面处理程序，包含两种用途：

- **桌面黑洞**：在鼠标附近生成黑洞，对黑洞周围真实显示的窗口、文字和视频产生引力透镜式扭曲。
- **桌面反畸变**：预先把整个桌面按相反方向弯曲，用来补偿弯曲镜面造成的桶形或枕形畸变。

程序不会修改桌面文件、应用窗口或 Windows 的输入系统。它取得当前显示器的画面，在 GPU 中重新排列像素，然后用一个置顶覆盖窗口显示处理后的结果。退出程序后，覆盖窗口消失，原桌面不会发生任何改变。

## 它解决什么问题

普通程序只能控制自己的窗口，无法直接让资源管理器、浏览器或第三方软件一起变形。本项目采用“捕获桌面再覆盖显示”的方式，把整个显示器当成一张实时更新的纹理，因此可以统一处理屏幕上已经合成好的内容，而不需要修改 Explorer、DWM 或每个目标程序。

```text
真实桌面和应用窗口
        │
        ▼
捕获当前显示器画面
        │
        ▼
GPU Shader 重新计算像素位置
        │
        ▼
置顶、无焦点、鼠标穿透的覆盖窗口

键盘和鼠标 ──────────────────> 下方真实应用窗口
```

这是一种视觉覆盖方案，不是显示驱动或系统级后处理。因此登录界面、UAC 安全桌面、DRM 保护内容和部分独占全屏程序不在它的处理范围内。

## 推荐：原生 DirectX 长期版本

`native/` 中提供了不依赖 Electron、Node.js 或 WebView 的 Win32 + Direct3D 11 实现。它通过 DXGI Desktop Duplication 在 GPU 内取得桌面纹理，并直接执行 HLSL 反畸变；桌面默认限制为 30 FPS，代理光标独立按 60 Hz 检查位置，画面和光标都无变化时跳过着色和 Present。

原生版本保留启动旁路、可见控制按钮、Esc/备用全局退出热键、系统托盘、15 分钟安全旁路以及独立进程看门狗。构建方法和架构说明见 [`native/README.md`](native/README.md)。

```powershell
npm.cmd run dist:native
```

下面的 Electron 版本继续保留，便于兼容和对照测试。黑洞模式目前由 Electron + WebGL 实现；原生版本主要用于低负载、长期运行的全桌面反畸变。

### 反畸变公式在做什么

反畸变不是把原桌面像素直接向外推，而是对覆盖层的每一个输出像素反向查询：

> 当前位置应该读取原桌面的哪个像素？

以畸变中心为原点，设当前像素相对中心的位置为 `(x, y)`：

```text
r² = x² + y²
radial = 1 + k1·r² + k2·r⁴
(sourceX, sourceY) = radial · (x, y) / zoom
```

然后从 `(sourceX, sourceY)` 对应的桌面位置读取颜色。因为每一个输出像素都会主动寻找一个源像素，所以不会出现正向推像素时常见的空洞和裂缝。

参数的直观作用：

| 参数 | 作用 |
| --- | --- |
| `k1` | 主曲率，控制从中心到边缘的整体弯曲，是第一个需要调整的参数 |
| `k2` | 边缘高阶曲率，主要修正四角和最外侧残留的弯曲 |
| `zoom` | 整体缩放，用来减少黑边或边缘裁切 |
| `centerX / centerY` | 畸变中心；中心不准会表现为左右或上下无法同时调直 |

当前模型是中心对称的径向模型，同一个半径上的所有方向使用相同修正量。如果镜面畸变也基本中心对称，那么调整 `k1` 时横线和竖线应当一起接近直线，再用 `k2` 修四角即可。

它适合以下情况：

- 左右弯曲基本对称；
- 上下弯曲基本对称；
- 横向和纵向需要的曲率接近；
- 畸变从中心向边缘平滑增加；
- 镜面没有明显局部凹凸。

如果出现横线直了但竖线仍明显弯、画面呈梯形、四个角形状不同或局部凹凸不均匀，就需要横纵独立参数、透视校正或控制点网格，而不是继续增大 `k1`、`k2`。

### 建议标定顺序

1. 把眼睛或摄像机固定在最终观察位置，标定过程中不要移动。
2. 调整 `centerX / centerY`，让左右和上下的弯曲尽量对称。
3. 调整 `k1`，让横线、竖线整体同时接近直线。
4. 调整 `k2`，修正四角剩余弯曲。
5. 调整 `zoom`，处理黑边和裁切。
6. 隐藏网格，用文字、窗口边框和实际内容复查效果。

## 焦点、键盘和鼠标

覆盖层虽然显示在最上方，但被设置为不可聚焦并忽略鼠标事件，因此它只负责显示，不负责接收普通输入：

- 原来聚焦的目标程序继续接收普通键盘输入；
- 鼠标点击穿过覆盖层，交给下方真实窗口；
- 点击反畸变控制面板时，控制面板会像普通窗口一样暂时获得焦点；
- 程序注册的全局快捷键是例外，对应按键会由本程序处理。

需要区分“输入能否到达”和“视觉坐标是否一致”：Windows 仍按未畸变的真实坐标判断按钮位置，而覆盖层中的按钮可能已经在视觉上发生移动。

原生 DirectX 版本已经实现代理光标：启用反畸变后，它隐藏真实系统光标，把当前 Windows 光标绘制到桌面源坐标中，再让光标与桌面一起经过同一个 Shader。因此用户看到的光标会与畸变后的按钮保持对齐，Windows 底层仍使用原始坐标向目标程序发送输入。鼠标进入控制面板、离开当前显示器、切回旁路或退出程序时会立即恢复真实光标；独立看门狗也会在主进程异常终止时执行恢复。

全屏 DirectX 覆盖层使用 `WS_EX_LAYERED | WS_EX_TRANSPARENT`，因此 Windows 的鼠标命中会跨进程跳过它，点击直接交给下面的真实程序；右侧控制面板是独立窗口，仍然可以正常操作。这里不能只依赖 `HTTRANSPARENT`，因为它只保证在同一线程的窗口之间继续查找。

Electron 兼容版本暂未接入系统级光标隐藏，因此在强畸变区域仍可能出现视觉位置与点击位置不一致。

## 工作原理

- Electron 版本通过桌面捕获 API 获取显示器画面；原生版本通过 DXGI Desktop Duplication 直接取得 GPU 纹理。
- 黑洞模式只覆盖黑洞附近，反畸变模式在启用时覆盖整个显示器。
- 覆盖窗口不会取得键盘焦点，并忽略鼠标命中，真实应用仍在下方正常运行。
- 覆盖层会从桌面捕获中排除，避免程序再次捕获自己的输出而形成无限镜像。
- 黑洞 Fragment Shader 根据到事件视界的距离改变 UV，模拟引力透镜；吸积盘、光子环、色差和流动细丝由 GLSL 实时生成。
- 反畸变 Shader 使用 `k1 + k2` 径向多项式预先弯曲桌面，使它经过真实镜面后尽量恢复成直线。

## 已知限制

- 当前版本针对 Windows 10 2004 及以上。
- 带 DRM/硬件保护的视频可能在桌面捕获中显示为黑色，这是系统限制。
- 某些全屏独占游戏会绕过桌面合成器；使用无边框窗口模式通常可以显示覆盖层。
- 运行时会持续进行屏幕捕获和 GPU 渲染，笔记本电脑耗电会增加。
- 捕获、着色和显示至少会引入少量帧延迟，不适合作为对延迟极其敏感的显示链路。
- 当前径向模型只处理平滑、中心对称的畸变，不能自动校正梯形、非对称或局部凹凸。
